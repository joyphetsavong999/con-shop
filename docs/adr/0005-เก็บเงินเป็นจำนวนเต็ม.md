# เก็บจำนวนเงินเป็นจำนวนเต็มหน่วยสตางค์

ทุกจำนวนเงินในระบบเก็บเป็นจำนวนเต็มหน่วยสตางค์ (integer) ไม่ใช้เลขทศนิยม

เหตุผลที่โครงสร้างราคาเอื้อให้: ราคาเก็บเป็นต่อหน่วยพื้นฐาน และจำนวนที่ขายเป็นจำนวนเต็มเสมอ (ดู ADR-0001)
เมื่อคูณกันจึงได้ผลลัพธ์ที่เป๊ะ ไม่มีทางเกิดเศษระหว่างทาง ส่วนตัวคูณของหน่วยขายก็เป็นจำนวนเต็มเสมอ
เลขทศนิยมจึงเป็นความเสี่ยงที่ไม่จำเป็น

## Considered Options

- **เก็บเป็นทศนิยมสองตำแหน่ง (เช่น 190.00)** อ่านง่ายกว่าในโค้ดแต่ทศนิยมในโฟลตเป็นเลขที่ไม่แน่นอน
  การคูณสะสมหลายรายการจะทำให้ยอดคลาดเคลื่อน ซึ่งในร้านวัสดุก่อสร้างที่ยอดบิลหลักหมื่นบาทถือว่ายอมรับไม่ได้
- **เก็บเป็นทศนิยมแต่คิดยอดเป็นจำนวนเต็มทีหลัง** เป็นการย้อนกลับมาใช้จุดปัดเศษที่ปลายสุด ซึ่งแย่กว่าการไม่มีเศษตั้งแต่ต้น

## Consequences

- ต้องมีจุดแปลงเป็น/จากสตางค์ตอนขอบของระบบ (แสดงผล และรับ input จากฟอร์ม) เท่านั้น
- หากภายหลังต้องคิดราคาต่อหน่วยวัดหรือคิดส่วนลดเป็นเปอร์เซ็นต์ ต้องระวังการปัดให้ถูกทิศทาง
  เพราะจะไม่มีจุดให้ยอมให้เศษอัตโนมัติอีกแล้ว
- ค่าขนส่งที่คิดจากน้ำหนักหรือระยะทาง (นอกขอบเขตสเปกนี้) จะเป็นจุดที่ต้องตัดสินใจเรื่องการปัดอย่างจริงจัง
